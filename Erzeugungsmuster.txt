
***Erzeugungsmuster (Creational Patterns)*** 

sind in der Softwareentwicklung wie Baupläne für Objekte. 
Statt Objekte einfach wahllos mit new zu erstellen, helfen uns diese Muster, 
den Erstellungsprozess flexibler und übersichtlicher zu gestalten.

1. ***Singleton (Das "Es darf nur einen geben"-Prinzip)***

Stell dir vor, du hast ein Programm mit Einstellungen 
(z. B. Lautstärke). Du willst nicht, 
dass an fünf verschiedenen Stellen im Code unterschiedliche Einstellungen existieren.

Man benutzt einfach eine normale Variable in einer Datei. 
Aber wenn wir eine Klasse nehmen, sieht das so aus:

class Einstellungen:
    instanz = None  # Hier "parken" wir unser einziges Objekt

    def __init__(self):
        # Wir prüfen: Haben wir schon eine Instanz geparkt?
        if Einstellungen.instanz is not None:
            print("Stopp! Es gibt schon Einstellungen!")
        else:
            self.lautstärke = 50
            Einstellungen.instanz = self
            print("Einstellungen wurden erstellt.")

# Testen:
eins = Einstellungen()  # Erstellt die Einstellungen
zwei = Einstellungen()  # Gibt nur die Warnung aus

Warum? Damit du nicht aus Versehen zwei verschiedene 
Datenbank-Verbindungen oder Einstellungs-Dateien gleichzeitig öffnest und Chaos verursachst.

2. ***Factory (Die "Wunsch-Maschine")***

Stell dir vor, du baust ein Spiel. 
Du willst nicht jedes Mal Zombi() oder Drache() tippen, sondern einfach sagen: 
"Gib mir ein leichtes Monster" oder "Gib mir ein schweres Monster".

class Zombi:
    def info(self): return "Ein schwacher Zombi erscheint!"

class Drache:
    def info(self): return "Ein mächtiger Drache erscheint!"

# Die "Fabrik" ist einfach eine Funktion mit einem 'if'
def erschaffe_monster(schwierigkeit):
    if schwierigkeit == "leicht":
        return Zombi()
    if schwierigkeit == "schwer":
        return Drache()

# Anwendung:
mein_gegner = erschaffe_monster("leicht")
print(mein_gegner.info()) # Ausgabe: Ein schwacher Zombi erscheint!
Warum? Dein Hauptprogramm muss nicht wissen, welche Tier-Klassen es gibt. #
Es bestellt einfach per Name (String).

3. ***Builder (Der "Schritt für Schritt"-Baukasten)***

Stell dir vor, du willst einen Burger konfigurieren. 
Manche wollen Käse, manche nicht. 
Statt 20 verschiedene Burger-Klassen zu schreiben, baust du ihn einfach zusammen.

class Burger:
    def __init__(self):
        self.zutaten = "Brot"

    def füge_käse_hinzu(self):
        self.zutaten += " + Käse"
        
    def füge_fleisch_hinzu(self):
        self.zutaten += " + Fleisch"

# Anwendung für einen Anfänger:
mein_burger = Burger()
mein_burger.füge_käse_hinzu()
mein_burger.füge_fleisch_hinzu()

print(mein_burger.zutaten) # Ausgabe: Brot + Käse + Fleisch

Warum? Es verhindert Fehler bei riesigen Objekten. 
Du kannst nichts vergessen und der Code sieht fast aus wie ein englischer Satz.

Was du dir merken kannst:
Singleton: Benutze ein if, um zu verhindern, dass ein zweites Objekt erstellt wird.

Factory: Benutze eine Funktion mit if/else, um zu entscheiden, welches Objekt gebaut wird.

Builder: Baue ein Objekt nicht sofort fertig, sondern rufe nacheinander Funktionen auf (wie füge_zutat_hinzu).


Welches:  Muster soll ich wählen?
Muster                                 Wann

Singleton:     Wenn es exakt eins von etwas geben darf (z.B. Konfiguration).

Factory:       Wenn du Objekte erstellen willst, ohne die genaue Klasse zu kennen.

Builder:        Wenn ein Objekt komplex ist oder viele optionale Teile hat.
