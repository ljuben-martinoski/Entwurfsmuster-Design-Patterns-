Erzeugungsmuster (Creational Patterns) sind in der Softwareentwicklung wie Baupläne für Objekte. 
Statt Objekte einfach wahllos mit new zu erstellen, helfen uns diese Muster, 
den Erstellungsprozess flexibler und übersichtlicher zu gestalten.

1. Singleton (Der "Einfach nur einer"-Club)
Stell dir vor, es gibt in einer Firma nur einen Chef. 
Egal, wen du fragst, alle zeigen auf dieselbe Person. 
In Python nutzen wir dafür oft eine einfache Logik in der __new__-Methode (die Methode, die das Objekt tatsächlich erschafft).

Python
class Chef:
    _instanz = None  # Hier speichern wir den einen Chef

    def __new__(cls):
        # Wenn noch kein Chef da ist, erschaffe einen
        if cls._instanz is None:
            cls._instanz = super(Chef, cls).__new__(cls)
            cls._instanz.name = "Der große Boss"
        return cls._instanz

# Testen:
chef1 = Chef()
chef2 = Chef()

print(chef1 is chef2)  # True! Es ist exakt dasselbe Objekt.
Warum? Damit du nicht aus Versehen zwei verschiedene Datenbank-Verbindungen oder Einstellungs-Dateien gleichzeitig öffnest und Chaos verursachst.

2. Factory (Die "Wunsch-Maschine")
Stell dir einen Getränkeautomaten vor. 
Du drückst auf "Kaffee" oder "Tee". 
Du musst nicht wissen, wie die Maschine das Wasser kocht oder den Beutel taucht – du sagst nur, 
was du willst.

Python
class Hund:
    def sprechen(self): return "Wau!"

class Katze:
    def sprechen(self): return "Miau!"

# Die Fabrik-Funktion
def tier_fabrik(typ):
    tiere = {
        "hund": Hund(),
        "katze": Katze()
    }
    return tiere.get(typ, "Unbekanntes Tier")

# Anwendung:
mein_tier = tier_fabrik("hund")
print(mein_tier.sprechen())  # Wau!
Warum? Dein Hauptprogramm muss nicht wissen, welche Tier-Klassen es gibt. Es bestellt einfach per Name (String).

3. Builder (Der "Subway-Sandwich"-Stil)
Wenn du bei Subway ein Sandwich bestellst, sagst du: 
"Brot, dann Käse, dann bitte toasten, dann kein Fleisch." 
Du baust es Schritt für Schritt. Ohne Builder müsstest du dem Verkäufer 20 Zutaten gleichzeitig zurufen.

Python
class Sandwich:
    def __init__(self):
        self.zutaten = []

    def hinzufügen(self, zutat):
        self.zutaten.append(zutat)

class SandwichBuilder:
    def __init__(self):
        self.sandwich = Sandwich()

    def mit_brot(self, typ):
        self.sandwich.hinzufügen(f"{typ} Brot")
        return self # Erlaubt "Chaining" (Verkettung)

    def mit_belag(self, belag):
        self.sandwich.hinzufügen(belag)
        return self

    def fertigstellen(self):
        return self.sandwich

# Anwendung:
mein_essen = (SandwichBuilder()
              .mit_brot("Vollkorn")
              .mit_belag("Käse")
              .mit_belag("Tomate")
              .fertigstellen())

print(mein_essen.zutaten) # ['Vollkorn Brot', 'Käse', 'Tomate']
Warum? Es verhindert Fehler bei riesigen Objekten. 
Du kannst nichts vergessen und der Code sieht fast aus wie ein englischer Satz.


Welches:  Muster soll ich wählen?
Muster                                 Wann

Singleton:     Wenn es exakt eins von etwas geben darf (z.B. Konfiguration).

Factory:       Wenn du Objekte erstellen willst, ohne die genaue Klasse zu kennen.

Builder:        Wenn ein Objekt komplex ist oder viele optionale Teile hat.
